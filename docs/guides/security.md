# Безопасность

GraphQL-эндпоинт — это один URL, который принимает **произвольные** запросы. Ниже описано, от чего защищает ядро, что включено по умолчанию и что стоит включить в продакшене.

## Конфигурация для продакшена

```ts
const graphqlHTTP = graphqlHTTPFactory({
  schema,
  middleware: [authMiddleware],
  debug: false,                                         // по умолчанию
  maskErrors: true,
  onError: error => logger.error(error),
  csrfPrevention: true,                                 // если авторизация на cookie
  introspection: process.env.NODE_ENV !== 'production',
  // persistedQueriesOnly: true,                        // если клиенты используют persisted queries
});
```

## Что включено по умолчанию

| Защита | От чего | Настройка |
|--------|---------|-----------|
| Лимит размера JSON-тела | Перегрузка памяти | `maxJSONBodySize`, 1 МБ |
| Лимит размера после распаковки | Gzip-бомба: 50 КБ сжатых данных → 50 МБ | `maxJSONBodyDecompressedSize`, 5 МБ |
| Потоковая загрузка файлов с лимитами | Перегрузка памяти и диска | [Загрузка файлов](./file-uploads.md) |
| Проверка путей в `map` | Prototype pollution: подмена `Object.prototype` всего процесса | Всегда |
| Лимит токенов | Огромные документы | `maxGraphQLTokens`, 10 000 |
| Лимит глубины | `{ a { b { a { b { … } } } } }` | `maxGraphQLDepthLimit`, 20 |
| Лимит сложности | `users(first: 1000) { friends(first: 1000) { … } }` | `complexityLimit`, 50 000 |
| Лимит ширины | Тысячи полей или алиасов в одном блоке | `maxFieldsPerSelection`, 50 |
| Изоляция запросов | Утечка данных между пользователями | Контекст создаётся на каждый запрос |
| Мутации только через POST | Изменение данных GET-ссылкой | Всегда |

### Глубина и сложность

Глубина считает вложенность полей: фрагменты уровня не добавляют. Сложность оценивает объём работы:

```
стоимость поля = (fieldCost + стоимость вложенных полей) × множитель списка
```

Множитель берётся из аргументов `first`, `last`, `limit`, `take`, `pageSize`, `size`: из литерала, из переменной, а если аргумент не передан — из значения по умолчанию в схеме (`items(first: Int = 100)`). Если передано несколько аргументов, берётся наибольший. Фрагмент, упомянутый N раз, учитывается N раз. Оба правила работают за линейное время от размера запроса: стоимость каждого фрагмента вычисляется один раз (мемоизация). Поэтому запрос, в котором фрагменты многократно ссылаются друг на друга, не может «повесить» сервер на этапе валидации.

Сложность примерно равна числу значений в ответе. Значения по умолчанию подобраны по реальным запросам biotransfer (443 операции CRM и мобильных приложений): глубина самой глубокой операции 10, медиана сложности 25, самые тяжёлые 13 000–41 000. Лимит 50 000 пропускает их и отклоняет `items(first: 1000) { items(first: 1000) { id } }` (2 001 000).

Как подобрать `maxComplexity` для своего проекта: включите `onComplete`, соберите распределение сложности реальных запросов клиентов и поставьте лимит с запасом над максимумом.

```ts
complexityLimit: {
  maxComplexity: 20_000,
  onComplete: complexity => metrics.histogram('graphql_complexity').observe(complexity),
},
```

### Кэш документов

Результат разбора и стандартной валидации кэшируется по тексту запроса: до 1000 документов и до 2 МБ суммарной длины текстов. Двойной лимит не даёт заполнить память уникальными запросами. Правила глубины, сложности и правила из middleware выполняются на каждый запрос.

## Что включить вручную

### `maskErrors`

Без маскирования клиент видит текст любого исключения. Например, ошибка драйвера БД может выглядеть так: `relation "users" does not exist at pg://admin:secret@10.0.0.5/db`. С `maskErrors: true` клиент получает `Internal server error`, а оригинал уходит в `onError`.

Перед включением переведите ошибки, которые должен видеть пользователь, на `GraphQLError`:

```ts
// было: при maskErrors пользователь увидит «Internal server error»
throw new Error('Недостаточно средств');

// стало: сообщение увидит пользователь
throw new GraphQLError('Недостаточно средств', { extensions: { code: 'INSUFFICIENT_FUNDS' } });
```

Подробнее — в разделе [Ошибки](./errors.md#маскирование-maskerrors).

### `csrfPrevention`

**Нужна, если авторизация основана на cookie.**

Браузер отправляет GET-запросы и `multipart/form-data` POST-запросы на любой сайт **без CORS-preflight** и прикладывает cookie этого сайта. Чужая страница может отправить такой запрос от имени пользователя, например выполнить мутацию загрузки файла. Прочитать ответ она не сможет, но сама мутация будет выполнена.

С `csrfPrevention: true` такие запросы обязаны содержать непустой заголовок из `CSRF_PREVENTION_HEADERS`:

```
x-requested-with
apollo-require-preflight
x-apollo-operation-name
graphql-preflight
```

Браузер не может добавить нестандартный заголовок к кросс-доменному запросу без preflight, а preflight контролирует сервер (CORS). Запросы с `Content-Type: application/json` всегда требуют preflight, поэтому проверка их не затрагивает.

На клиенте заголовок нужно добавить явно:

```ts
// Apollo Client + apollo-upload-client
const link = createUploadLink({
  uri: '/graphql',
  headers: { 'apollo-require-preflight': 'true' },
});

// fetch / XMLHttpRequest
fetch(`/graphql?query=${encodeURIComponent(query)}`, { headers: { 'x-requested-with': 'XMLHttpRequest' } });
```

Если авторизация только через заголовок `Authorization`, CSRF невозможен: браузер не добавляет этот заголовок сам.

### `introspection`

Introspection (`__schema`, `__type`) позволяет получить всю схему: типы, поля, аргументы, описания. Это удобно в разработке (GraphiQL, codegen), но в проде облегчает поиск слабых мест. `introspection: false` запрещает эти поля, а `__typename` работает всегда.

Это не замена авторизации: имена полей можно подобрать перебором, а graphql-js подсказывает похожие имена в ошибках («Did you mean…»).

### `persistedQueriesOnly`

Самая строгая защита: сервер выполняет только запросы из заранее известной карты. Все лимиты сложности перестают быть критичными, потому что произвольный запрос просто не пройдёт. Требует поддержки на клиенте, см. [Persisted Queries](./persisted-queries.md).

## Что остаётся на вашей стороне

| Тема | Рекомендация |
|------|--------------|
| Авторизация | Проверяйте права в каждом резолвере или в обёртке (`fieldsWrapper`), не полагайтесь на то, что клиент «не знает» о поле |
| Курсоры пагинации | Курсор приходит от клиента: проверяйте его, а ограничения доступа берите из контекста. См. [Connections](./connections.md#курсор) |
| Имена и типы файлов | Не используйте `filename` как путь, тип проверяйте по содержимому. См. [Загрузка файлов](./file-uploads.md) |
| Rate limiting | Ограничивайте число запросов с одного клиента на уровне прокси или middleware |
| Таймауты | Настройте `server.requestTimeout` и `server.headersTimeout` у HTTP-сервера Node.js |
| CORS | Ядро не обрабатывает CORS и `OPTIONS`-запросы. Это задача вашего HTTP-сервера |
| `debug` | Только в разработке: раскрывает стеки вызовов и статистику сервера |
