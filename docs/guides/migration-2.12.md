# Миграция на 2.12

Публичный API 2.12 совместим с 2.10 (версия 2.11 не публиковалась): функции, параметры и типы сохранены, новые параметры необязательны. Но часть **поведения** изменилась: это исправления ошибок и уязвимостей. Пройдите по чек-листу перед обновлением проекта.

## Чек-лист

### 1. Контекст создаётся на каждый запрос

**Что изменилось.** Раньше `context` был одним объектом на все запросы. Теперь каждый запрос получает новый пустой объект.

**Что проверить.** Найдите в middleware ленивую инициализацию долгоживущих объектов:

```ts
// ❌ при новом поведении пул будет создаваться на каждый запрос
const dbMiddleware: Middleware = ({ context }) => {
  if (!context.knex) {
    context.knex = createKnex(config);
  }
};
```

**Как исправить.** Создавайте такие объекты при старте приложения:

```ts
// ✅
const knex = createKnex(config);

const dbMiddleware: Middleware = ({ context }) => {
  context.knex = knex;
};
```

Если быстро исправить нельзя, временно включите прежнее поведение:

```ts
graphqlHTTPFactory({ schema, sharedContext: true }); // устарело: данные запросов не изолированы
```

Поищите в коде: `grep -rn "if (!context\." src/`.

### 2. Лимит ширины запроса `maxFieldsPerSelection: 50`

**Что изменилось.** Значение было объявлено и раньше, но не применялось. Теперь запрос, в котором один блок `{ }` содержит больше 50 полей (включая алиасы), отклоняется с ошибкой `A selection set contains N fields`.

**Что проверить.** Самые «широкие» запросы фронтендов: формы, экспорт, отчёты. При необходимости увеличьте лимит:

```ts
limits: { complexityLimit: { maxFieldsPerSelection: 150 } }
```

### 3. Лимит сложности учитывает переменные и каждый фрагмент

**Что изменилось.** Раньше `users(first: $n)` считался с множителем 1, а фрагмент, использованный несколько раз, учитывался один раз. Теперь сложность считается честно, и некоторые запросы, проходившие раньше, могут превысить `maxComplexity`. Множитель также берётся из `last` и из значения аргумента по умолчанию в схеме. Чтобы честный подсчёт не сломал реальные запросы, значение по умолчанию поднято с 5000 до 50 000 (подобрано по запросам biotransfer). Если в проекте был задан `maxComplexity: 50000000` (фактически выключенный лимит), уберите его и проверьте запросы с `onComplete`.

**Что проверить.** Временно включите `onComplete`, посмотрите сложность реальных запросов и подберите лимит:

```ts
limits: { complexityLimit: { onComplete: c => console.log('complexity', c) } }
```

### 4. Скаляры строже проверяют вход

| Скаляр | Больше не принимается | Что слать |
|--------|----------------------|-----------|
| `DateTime` | Строки не в ISO 8601 (`"05.03.2026"`), несуществующие даты (`"2026-02-30"`), timestamp в секундах | ISO 8601, лучше UTC: `date.toISOString()` (JS), `toUtc().toIso8601String()` (Dart) |
| `Money` | `""`, `" 100 "`, `"0x64"`, числа | Строка из цифр: `"10000"` |
| `Time` | `"24:30"` и другие `24:xx`, кроме `24:00` | `"HH:MM"` или `"HH:MM:SS"` |
| `URL` | `javascript:…`, `vbscript:…` | — |

Выход тоже изменился: `Time` теперь всегда возвращается в формате `HH:MM:SS` (`"9:05"` → `"09:05:00"`).

### 5. `extensions` есть в каждом ответе, статистика — только в `debug`

Теперь в каждом ответе есть `extensions.requestId` и поля проекта (`setExtension`, middleware). Статистика сервера (`queryTime`, `requestCounter`, `startupTime`) и диагностика отдаются только при `debug: true`. Подробнее в разделе [Extensions](./extensions.md).

**Что сделать.** В маршрутах замените

```ts
extensions: debug ? extensions : undefined,
```

на `extensions`. Иначе поля проекта и `requestId` не дойдут до клиента в проде. Проверьте, не читает ли фронтенд или мониторинг статистику без `debug`.

`validationRule` в middleware теперь изначально пуст: правила глубины и сложности ядро применяет отдельно.

### 6. Загрузка файлов

- Временные файлы **удаляются автоматически** после отправки ответа. Резолвер должен прочитать или скопировать файл до этого момента. Фоновая обработка «после ответа» должна сначала скопировать файл.
- Вызов `cleanup()` больше не обязателен, но и не мешает.
- Multipart-тело обязано использовать переводы строк CRLF, как требует RFC. Браузеры и HTTP-библиотеки так и делают; проблема возможна только с самописными клиентами.
- `mimeType` теперь в нижнем регистре и без параметров: `"image/png"`, а не `"Image/PNG; charset=binary"`.
- `DEFAULT_MAX_FIELD_SIZE` уменьшен до 1 МБ: поле `operations` больше 1 МБ отклоняется. Если нужно больше, задайте `limits.maxFieldSize`.

### 7. Ошибки разбора запроса стали явными

| Запрос | 2.10 | 2.12 |
|--------|------|------|
| Невалидный JSON | `The request is empty` | `The request body is not valid JSON: …` |
| `variables` — массив или число | Принимались | `Variables must be an object.` |
| Batch-запрос (массив операций) | `The request is empty` | `Batched operations are not supported` |

### 8. Introspection снова работает по умолчанию

Из-за ошибки в 2.10 стандартный introspection-запрос (GraphiQL, codegen) отклонялся при настройках по умолчанию. Теперь он работает. Если introspection не нужен в проде, отключите его явно: `introspection: false`.

### 9. Типы

Удалены объявления `CoreService` и `BetweenDateInputType`: их не было в рантайме, и код с ними падал при запуске. `BetweenMoney.start/end` теперь `bigint`.

## HTTP-статусы

Ядро теперь возвращает рекомендуемый статус в `response.status` (см. [Ошибки → HTTP-статусы](./errors.md#http-статусы)). Поле неперечисляемое, поэтому ничего не ломает. Чтобы им воспользоваться, замените в проекте выставление статуса:

```ts
res.statusCode = response.status ?? 200;
```

Перед этим убедитесь, что клиенты проекта корректно обрабатывают ответы `4xx` с GraphQL-телом. Apollo Client, urql и Relay с этим справляются.

## Что включить после обновления

Новые параметры безопасности по умолчанию выключены, чтобы не ломать проекты. Рекомендуется включать их по одному:

1. `onError`: подключите к логгеру, это безопасно.
2. `maskErrors: true`: после перевода «пользовательских» ошибок на `GraphQLError` (см. [Ошибки](./errors.md#маскирование-maskerrors)).
3. `csrfPrevention: true`: если авторизация на cookie, после добавления заголовка на клиентах (см. [Безопасность](./security.md#csrfprevention)).
4. `introspection: false` в проде.
5. Пагинация: замените свою реализацию курсоров в `BaseService` функциями ядра (см. [Пагинация](./connections.md#переход-со-своего-baseservice)). Это закрывает подмену фильтров через курсор. Учтите, что после перехода старые неподписанные курсоры перестанут приниматься.
6. Создавайте обработчик `graphqlHTTPFactory(...)` один раз при старте, а не внутри маршрута на каждый запрос. Иначе кэш разобранных документов не работает.
